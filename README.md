# 🧸 Світ Іграшок — навчальний інтернет-магазин

Повний цикл покупки на **Node.js 24 + Express 5 + SQLite + HTML/CSS/JavaScript**.
Збережено логотип, банери, рожеву палітру та Nunito вихідного макета. Українська мова, ціни у гривнях.

## Запуск у Windows

Відкрийте PowerShell у корені `!toy-shop-course-work` (не в `src`):

```powershell
npm.cmd ci
npm.cmd run admin
npm.cmd start
```

- Магазин: <http://127.0.0.1:3000>
- Адмінка: <http://127.0.0.1:3000/admin.html>
- При першому запуску створюється `data/shop.sqlite` із 28 демонстраційними товарами, 14 основними категоріями та 3 підкатегоріями.
- `npm run admin` створює адміністратора з випадковим паролем. Дані входу — у **`data/admin-access.txt`**. Спочатку увійдіть через кнопку «Увійти» у магазині, потім відкрийте «Адмінка».
- Якщо адміністратор уже створений, повторювати `npm run admin` не потрібно. Повторна команда не змінює його пароль.
- Зупинка сервера: `Ctrl+C`. Повторний запуск зберігає товари, акаунти та замовлення.
- Для розробки: `npm.cmd run dev` (автоматичний перезапуск сервера).

**Потрібен Node.js 24 або новіший.** SQLite вбудована в Node.js; окремий сервер БД не потрібен.
Файл `src/index.html` потрібно відкривати через сервер, не подвійним клацанням і не через Live Server. GitHub Pages не запускає Node.js та БД.

## Що працює

- Каталог через API: підкатегорії, пошук українською без урахування регістру, бренд, ціна, рекомендований вік, наявність, знижки, сортування та пагінація.
- Сторінка товару, залишок на складі, опис, ціна та знижка.
- Реєстрація, вхід, вихід, ролі покупця й адміністратора. Паролі зберігаються як scrypt-хеші, сесія — у HttpOnly cookie.
- Гостьова кошик в браузері; після входу переноситься до БД. Кошик користувача та обране зберігаються між сеансами.
- Оформлення замовлення з контактами, самовивозом або адресою доставки, коментарем і оплатою при отриманні.
- Кабінет з історією замовлень, складом покупки й актуальним статусом.
- Адмінка: створення та редагування товарів, завантаження PNG/JPG/WebP до 5 МБ, приховування/повернення товарів, категорії та їх вкладеність, залишки, замовлення, ролі й блокування користувачів.
- Скасування замовлення повертає залишки один раз. Сервер забороняє повторний продаж останньої одиниці.

Нові демонстраційні товари використовують ілюстрації категорій. Оригінальні фото LEGO збережено. Їх можна замінити власними фотографіями через адмінку. Несправжні відгуки й рейтинги старого макета прибрано.
Сертифікати є демонстраційними товарами; окремої системи активації та погашення сертифікатів немає.

## Налаштування

Необов'язково скопіюйте `.env.example` у `.env`:

```powershell
Copy-Item .env.example .env
```

| Змінна                      | Призначення                                                                   |
| --------------------------- | ----------------------------------------------------------------------------- |
| `PORT`                      | Порт, типово 3000                                                             |
| `HOST`                      | Типово `127.0.0.1`, тільки локальний комп'ютер                                |
| `DATABASE_PATH`             | Файл SQLite, типово `./data/shop.sqlite`                                      |
| `COOKIE_SECURE`             | `true` для HTTPS; локально `false`                                            |
| `ADMIN_EMAIL`, `ADMIN_NAME` | Дані нового адміністратора для команди `npm run admin`                        |
| `ADMIN_PASSWORD`            | Необов'язковий пароль 10–128 символів; якщо порожній — створюється випадковий |

`.env`, `data/` та завантажені фото не включаються в Git. Резервна копія магазину — це БД у `data/` та папка `src/uploads/`. Копіюйте їх після зупинки сервера, щоб не втратити дані SQLite WAL.

## Як розбирати проєкт студенту

1. Почніть із `src/index.html`: це оболонка сторінки, без вбудованого масиву товарів.
2. `src/js/main.js` відповідає за маршрути, форми, каталог і кошик. Маршрути мають вигляд `#catalog?category=1`.
3. `src/js/api.js` виконує HTTP-запити та передає CSRF-токен.
4. `server/app.js` підключає middleware і маршрути Express.
5. `server/catalog.js` будує параметризовані SQL-запити для пошуку та фільтрів.
6. `server/schema.sql` описує таблиці, зовнішні ключі та обмеження даних.
7. `server/orders.js` показує, для чого потрібна транзакція: замовлення, його позиції, списання залишків і очищення кошика виконуються разом.
8. `tests/shop.test.js` демонструє інтеграційні тести справжнього HTTP API зі справжньою тимчасовою SQLite.

### Приклад: натискання «У кошик»

```text
Кнопка data-buy у браузері
  → setQuantity() у main.js
  → PUT /api/cart/:id з кількістю
  → перевірка сесії та CSRF-токена
  → перевірка залишку товару сервером
  → INSERT / UPDATE у cart_items
  → JSON з актуальним кошиком
  → оновлення лічильника та вікна кошика
```

Ціна завжди визначається сервером. У БД суми зберігаються цілими копійками, щоб уникати похибок дробових чисел. Замовлення містить копію назви та ціни на момент покупки. Користувач не може змінити підсумок, підмінивши запит браузера.

### Структура

```text
server/
  index.js          запуск HTTP-сервера
  app.js            Express, захисні middleware, статика, помилки
  db.js             підключення SQLite та транзакції
  schema.sql        схема БД v1
  seed.js           одноразове початкове наповнення
  security.js       перевірка полів, хешування паролів
  auth.js           реєстрація, сесії, CSRF, права доступу
  catalog.js        відкритий каталог і фільтри
  orders.js         кошик, обране, замовлення, статуси
  admin.js          адміністративний API і фото
  payments.js       окремий модуль способів оплати
  create-admin.js   створення адміністратора з командного рядка
src/
  index.html        магазин
  admin.html        адмінка
  js/api.js         HTTP-клієнт
  js/ui.js          спільні компоненти та безпечний вивід тексту
  js/main.js        логіка магазину
  js/admin.js       логіка адмінки
  css/              вихідні стилі та app.css з доповненнями
  img/              вихідні зображення
  uploads/          фотографії, завантажені адміністратором
tests/shop.test.js  інтеграційні перевірки
docs/API.md        довідник API та модель даних
```

Для невеликого навчального проєкту синхронний SQLite API простіший за ORM: SQL видно безпосередньо. Для великої кількості запитів знадобляться PostgreSQL, пул підключень, міграції та винесення важких задач із HTTP-процесу.

## Майбутнє підключення оплати

`server/payments.js` відокремлює спосіб оплати від товарів і кошика. Зараз існує лише `offline` зі станом `pending`; виконане замовлення позначається сплаченим адміністратором через завершення замовлення.

Для онлайн-провайдера потрібно додати адаптер створення платіжної сесії, конфігурацію секретів і URL повернення, таблицю платіжних спроб та webhook із перевіркою підпису. Створюйте замовлення й резервуйте залишки в короткій транзакції, а мережевий виклик провайдера робіть **поза транзакцією**. Потрібні також ідемпотентність webhook, звірка суми/валюти, строк резерву та повернення залишків після прострочення оплати. Позначати оплату успішною лише за переходом браузера на сторінку «Успіх» не можна.

Реальних платіжних запитів, збереження карток, служб доставки та поштових розсилок у цій версії немає. Відновлення пароля через email теж потребує окремого поштового сервісу. Це локальний навчальний магазин; публічний запуск потребує HTTPS, резервних копій і налаштувань середовища розгортання.

## Перевірки та форматування

```powershell
npm.cmd test
npm.cmd run format
```

Тести ізольовані від робочої БД. Перевіряються пошук, фільтри, авторизація, права доступу, CSRF, кошик, обране, замовлення, конкурентна покупка, повернення залишків, CRUD, завантаження зображень, блокування та збереження даних.

Документація технологій: [Express](https://expressjs.com/), [SQLite у Node.js](https://nodejs.org/api/sqlite.html), [SQLite](https://sqlite.org/docs.html).
